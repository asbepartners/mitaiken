# マスタ・リスト構造の設計原則

## 目的

「わたしのはじめて帖」でマスタやリスト構造を追加・変更するときに、判断がぶれないための原則を定める。

## 1. マスタの役割

マスタには、次の2つの役割がある。

1. ユーザーが知らなかった、または思いつかなかった体験との出会いをつくる
2. 多くの人が普通に思いつく体験を、すぐに使える「記録の入れ物」として用意する

オリジナルのはじめてをユーザー自身が追加できるため、マスタですべての体験を網羅する必要はない。

マスタの件数を増やすこと自体を目的にせず、次のどちらかの価値を持つものを登録する。

- 定番として入力の手間を減らせる
- 「そんな体験もあるんだ」という発見を生み出せる

## 2. マスタは単体を基本とする

それだけで一つの目的になる体験は、単体のマスタとして登録する。

例：

- 錫のぐい呑みを作る
- ファイナンシャルプランナーの資格を取る
- 吹きガラスを体験する

カテゴリが同じ、または内容が似ているという理由だけで親子関係にはしない。

## 3. 親子関係は収集行為に限定する

親子関係は、同じ種類の対象を複数追加し、ひとつのリストとして集めていく行為に限定する。

親子関係に向いている例：

- 御朱印を集める → 神社・お寺ごとの記録
- 城を巡る → 城ごとの記録
- 温泉地を巡る → 温泉地ごとの記録

親子関係にしない例：

- 資格を取る → 英語資格、ファイナンシャルプランナー、簿記
- 伝統工芸を体験する → 錫器、染め物、切子
- スポーツを始める → ゴルフ、テニス、ヨガ

これらは分類上は似ていても、ひとつの収集行為ではないため、それぞれを単体のはじめてとして扱う。

### 親子関係の判断基準

次の両方を満たす場合だけ、親子関係を使用する。

1. 子をひとつ達成した後も、同じ型で次の対象を追加して集めていく行為が自然である
2. 複数の子をひとつの一覧で眺め、育てること自体に価値がある

## 4. カテゴリ・タグ・親子関係を使い分ける

| 要素 | 役割 |
| --- | --- |
| カテゴリ | 似た体験を見つけるための大きな棚 |
| タグ | 条件や特徴から横断的に探すための情報 |
| 親子関係 | 同じテーマの対象を複数集め、ひとつのリストとして育てる構造 |

分類のために親子関係を使用しない。

## 5. 「ものづくり体験」を独立カテゴリにする

「趣味」と「ものづくり体験」は、継続性によって区別する。

- 趣味：自分で始め、繰り返し続けていくことを主眼とする活動
- ものづくり体験：工房や教室などで、一度やってみることを主眼とする制作体験

例：

| 趣味 | ものづくり体験 |
| --- | --- |
| 編み物を始める | 錫のぐい呑みを作る |
| アクセサリー作りを始める | シルバーリング作りを体験する |
| 木工を始める | 木のスプーン作りを体験する |
| 陶芸を趣味にする | 陶芸体験で器を作る |

「伝統工芸」「作品が残る」「旅先でできる」などは、必要に応じてタグとして扱う。

「ものづくり体験」は、特に「そんな体験もあるんだ」という発見を提供しやすいカテゴリとして、定番と意外性のある体験をバランスよく用意する。

## 6. 単体項目を中心に導線を設計する

マスタは単体が基本となるため、単体項目を例外的な簡易表示として扱わない。

やってみたいリストでは、親子項目と単体項目のどちらもタップして詳細を確認できる状態を目指す。

単体の詳細で確認・操作できるようにする情報：

- タイトルと画像
- カテゴリ
- 場所・時間・予算などのタグ
- ユーザーが入力したメモ全文
- 参考URL
- やってみた記録
- リスト情報の編集・削除

一覧画面では情報量を抑え、詳しい情報や操作は詳細画面に分ける。

## 7. 新しいマスタ候補の確認手順

新しい候補を追加するときは、次の順番で判断する。

1. これは単体の体験か、収集型の体験か
2. どのカテゴリに置くか
3. 必要な検索タグは何か
4. マスタとして「定番」または「発見」の価値があるか
5. 既存マスタで十分に代替できないか

この原則に当てはまらない場合は、安易に親子構造や新しいカテゴリを増やさず、オリジナル登録で対応できるかを検討する。
